# Постоянный Instagram Direct-бот ACPro через официальный Facebook API

## Что это даёт

Этот режим **не использует Meta Webhooks и Plesk** для получения сообщений. Работает на Windows-компьютере с локальным Ollama/Qwen, опрашивает `graph.facebook.com` раз в **60 секунд** (с учётом длительности обработки запросов; при ограничениях Meta фактический интервал может быть больше), при наличии нового входящего Direct составляет ответ и, **только при явном включении**, отправляет ответ через официальный Page Send API.

Проверено пользователем ранее: `GET /1353920131143281/conversations?platform=instagram` с Facebook Page Access Token вернул пять настоящих диалогов. **Получение конкретных сообщений по `/{conversation-id}/messages` и отправку по `/{page-id}/messages` предстоит подтвердить на одном тестовом диалоге.** До этого не включать автоматические ответы всем.

### Что защищает от неприятностей

- На первом запуске запоминает текущую переписку и **не отвечает на старые сообщения**.
- Помечает новое сообщение обработанным **до попытки отправки**, чтобы не отправить дубль при сомнительном ответе сети.
- Не отвечает по собственной инициативе, старше 23 часов, на сообщения со странным или неизвестным отправителем, в диалогах человека-оператора, на сообщения без текста и на собственные сообщения.
- При жалобе или запросе человека отправляет контакт менеджера и приостанавливает чат на сутки.
- Публикуемых паролей, ключей или текстов переписок в GitHub и логах нет; локально хранятся только хеши ID обработанных сообщений и пауз чатов.
- `mode: dry_run` по умолчанию: чтение и локальная подготовка, **без отправки**.

**Ограничение:** это опрос, а не гарантированная мгновенная доставка; если ПК выключен, интернет отсутствует или Meta ограничивает права/rate limits, бот не ответит. Просматривает до 20 недавних диалогов × 10 сообщений. Поскольку это способ опроса, за один цикл возможно более 20 вызовов Graph API: при ограничениях Meta или росте переписок интервал нужно увеличить. Настройка нового файла по умолчанию `poll_seconds: 60`; если частота опроса вызовет rate limits, вернуться на 90–120 секунд. Для высокого потока потребуется пагинация и более надёжное фоновое приложение.

## Важно: защищённый новый токен

Один Page Access Token ранее попал в чат. **Отзови его и создай новый приватно в Meta.** Не используй раскрытый токен даже для тестовой отправки. Обновление токена **не должно** попадать в чат, скриншот, архив, GitHub или `acpro.kz`.

Если приложение в Developer Mode, не рассчитывай, что ответы всем клиентам будут разрешены без проверки прав Meta/App Review. Начинаем с тестировщика и проверяем официальный API.

## Установка на Windows

1. Скачай папку `automation/windows` из этой ветки или ZIP ветки в GitHub, распакуй на ПК. Ollama с `qwen3.5:4b` уже установлен.
2. Двойным щелчком запусти `START_DIRECT_POLL.cmd`. При первом запуске он создаст приватный файл `%APPDATA%\ACPro\facebook-direct.json` и откроет его в Блокноте.
3. В поле `facebook_page_access_token` вставь **новый** маркер именно Facebook-страницы `Astana Cleaning Pro`. Остальные значения уже указаны. **Не отправляй содержимое файла в чат.**
4. Оставь `"mode": "dry_run"`, `"allow_all_inbound": false`; сохрани файл. Снова запусти `START_DIRECT_POLL.cmd`.
5. Дождись текста `Baseline complete. Historical messages skipped. Send a NEW test Direct now.`
6. С разрешённого тестового Instagram-аккаунта отправь новое сообщение в `@astanacleaningpro`. После нового цикла ждём `DRY-RUN: one new incoming Direct processed...`.
7. Только после успешного dry-run и проверки безопасного ответа можно менять `"mode": "live"` и **указать локально IGSID тестового отправителя** в `"test_sender_id"`. Этот ID берётся из `from.id` конкретного сообщения через Graph API, не путать с ID страницы, Instagram бизнес-аккаунта или токеном.
8. После контролируемой успешной отправки тестировщику и проверки Meta App Review можно включить `"allow_all_inbound": true` для клиентов.

**Для остановки:** закрой окно или нажми Ctrl+C. **Для выключения ответов:** переключи `mode` обратно на `dry_run` и перезапусти. Смена конфигурации вступает в силу при перезапуске.

## Автозагрузка

После теста: Win+R → `shell:startup`, размести там ярлык `START_DIRECT_POLL.cmd`. Компьютер должен быть включён и не переходить в сон; вход в Windows обязателен. Лимиты Meta и условия предоставления доступа продолжают действовать.

## Технические детали

- Facebook Login: `GET /v26.0/{PAGE_ID}/conversations?platform=instagram&fields=id,updated_time&limit=20`, затем `GET /v26.0/{CONVERSATION_ID}/messages?fields=id,message,from,to,created_time&limit=10`.
- Ответ: `POST /v26.0/{PAGE_ID}/messages` с Page token, `recipient.id` равен **IGSID отправителя**, `messaging_type=RESPONSE`. Не путать с ID диалога.
- Программа принимает только сообщения с `from.id` клиента и адресованные странице или Instagram аккаунту через `to`. Если Graph API отдаёт иную структуру, программа **безопасно пропускает событие**, а не отправляет его непонятно кому.
- Поля `instagram_manage_messages`, `instagram_basic`, `pages_read_engagement`, `pages_show_list` требуются в пределах разрешений и уровня доступа приложения.
- Отвечаем только в установленное Meta окно после входящего сообщения; для безопасности в коде порог менее 23 часов.
- Состояние: `%APPDATA%\ACPro\facebook-direct-state.json`, не удалять при обычных перезапусках. Для обновления прав токена обновить приватную конфигурацию и перезапустить.
- Сайт `acpro.kz` не меняется; прежний серверный Webhook может продолжать быть подписанным, но **не должен отправлять дублирующие ответы**. `replies_enabled=false` на сервере до финальной миграции.
